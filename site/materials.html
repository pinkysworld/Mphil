Data Repository Working notes

Data

What is used and what stays local

Used in the project

The current runs are based on the reduced Avast-CTU CAPEv2 dynamic-analysis release together with the public family labels.

Kept outside Git

Raw archives, extracted reports, processed feature caches, and fitted model caches are stored locally and excluded from version control.

Why the reduced release is practical

It preserves the label definitions needed for the core study while making ingestion, caching, and repeated experiments much easier to manage.

Why the raw archive is not pushed

The dataset is large, third-party, and not something that belongs inside a normal Git history. The repository is meant to hold the research code and notes, not the raw malware corpus.

The public repository separates auditable research evidence from non-distributable or heavy inputs. The release inventory identifies the one authoritative dated bundle and all intentional archive copies.

Working Notes

Current reproducibility approach

  • Environment: the project is run in a local Python virtual environment pinned to the required scientific stack.
  • Dataset handling: the ingestion script unpacks the archive automatically and matches it to the public label file.
  • Intermediate products: large feature caches remain local; selected results and replay inputs needed for public verification are tracked.
  • Integrity: the dated evidence, policy outputs, and curated explanation archive are checked by scripts/verify_release.py.
  • Website: the site is deployed with GitHub Pages as a bounded public summary alongside the thesis and executable supplement.

Hosted with GitHub Pages. Code and defended evidence are public; raw dataset files and large generated caches remain local.
